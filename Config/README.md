<h2>结构</h2>
以Nacos为配置中心，将绝大多数配置交由Nacos进行管理
<ul>
<li>项目模块私有配置</li>
<li>JWT，Token，MQ队列，交换机等公共配置</li>
<li>服务模块公有配置和Bean对象</li>
</ul>
<h2>优点</h2>
<p>很多配置不用在别的模块重新再写，直接spring引入即可</p>
<p>公共配置后，一改全改，不用再担心可用性和维护性，同时还能让Nacos的动态刷新功能提一下开发速度</p>
<h2>缺点</h2>
<p>你将看到快百来行的Nacos日志（info级别屏蔽下）,以及你将见到超“快”的启动速度（反正我一次启动，等它完全初始化快要耗费10s了）</p>
<p>干啥都需要先在Nacos控制台写配置，然后在Config模块再写个读取配置类，然后再交给别的模块引入</p>
<p>可能使别的模块过度引入Bean对象，且会出现一些不兼容问题，如网关模块无法读取NativeConfig的配置，会直接报错</p>
