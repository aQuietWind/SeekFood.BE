<h2>优点</h2>
<p>这是这个项目能够做到一个复杂业务仅仅只用几行代码，几个方法就可以实现的根本，没有这个手写的Util模块，是很难快速开发的</p>
<h2>缺点</h2>
<p>虽然确实在略微影响性能的情况下实现了超快速开发（仅需理解一个接口的具体步骤，然后调几个方法，写几个参数即可），但是却影响到了Util模块的业务耦合性。
即，可能出现在这个项目适用，但是却不适用于别的项目的问题。</p>
<p>除了耦合性之外，还必须引入较多的依赖，使这个模块臃肿起来，不过对于这个项目来说，服务模块基本也要用到这些依赖，所以也就不成大问题了，但是，如果
放在很大的项目（微微细拆分可达50+服务模块）中，工程量急剧增大，这个Util模块可能不是较好的选择了，更加建议将整个Util模块按涉及依赖又进行拆分</p>
